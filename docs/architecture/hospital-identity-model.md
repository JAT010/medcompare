# Hospital Identity Model (Milestone 1)

## Core principle

**Every physical hospital facility has its own immutable UUID, independent of parent organization, brand, website domain, or extraction URL.**

- `Apollo Hospitals` (organization) ≠ `Apollo Hospital Delhi` (facility) ≠ `Apollo Hospital Chennai` (facility).
- Each facility gets a distinct, application-generated UUID at registration.
- Extraction datasets, runs, and recommendations (future milestones) must associate to a **facility UUID**, never to an organization or domain alone.

## Entities

### HospitalOrganization
Represents a parent brand/organization that may own multiple facilities.
- Identity: UUID PK (generated by application).
- Names/websites are metadata; **organization names are not globally unique** and not identity keys.

### HospitalFacility
Represents one individual physical hospital/location.
- Identity: **immutable UUID PK** (generated by application, never client-overwritten, never changed on update).
- May have nullable `organization_id` (unknown/unaffiliated initially).
- May have nullable `canonical_url` when a facility-specific URL is unknown.

## Non-negotiable identity rules

1. Every physical facility receives its own UUID.
2. Facility UUIDs are application-generated and **immutable** across name/address/org/URL updates.
3. One organization can own multiple facilities; a facility can exist without a known organization.
4. Facility names are **not** globally unique. Organization names are **not** globally unique.
5. Website domains are **not** globally unique and **not** identity keys.
6. Two branches may share the same domain and must remain separate facilities.
7. Never automatically merge facilities based on similar names, shared domains, or matching brands.
8. Use **soft deactivation** (`status=inactive`) instead of destructive deletion for registered facilities.
9. Arbitrary client-supplied UUIDs must not overwrite existing identities (service generates IDs).

## Canonical URL and duplicate handling

- `canonical_url` should identify **that facility** (e.g. a branch/location page), not merely a shared organization homepage.
- `canonical_url` is nullable; multiple facilities may have null canonical URLs.
- When present, `normalized_canonical_url` must be **unique across facilities**.
- Registering a URL that normalizes to an existing facility’s normalized canonical URL **fails with a clear conflict** identifying the existing facility UUID. **No silent merge.**
- A shared homepage domain (e.g. `https://apollohospitals.com/`) must not become the identity of every branch.
- Same domain + different facility-specific URL/path/query identity => allowed as separate facilities.
- Same domain alone is not a duplicate condition.

## URL normalization rules (deterministic, no network)

Implemented in `persistence.url_normalization.normalize_canonical_url`:

- Accept **HTTP/HTTPS only**; trim whitespace.
- Lowercase scheme and hostname; normalize IDN hostnames consistently (IDNA).
- Remove default ports (`:80`/`:443`).
- Remove URL fragments.
- Path normalized to stable identity form: root `/`; non-root paths have duplicate slashes collapsed and **trailing slash removed** (deterministic).
- **Preserve meaningful query parameters** and their order; do not drop arbitrary query params.
- No network requests, no redirect following, no inference that same-domain URLs are same facility.
- Invalid/malformed/non-http(s) URLs rejected with `InvalidFacilityUrlError`.

## Registration/update behavior

- Duplicate normalized canonical URL on create/update => `DuplicateCanonicalUrlError(existing_facility_id, normalized_url)`.
- Invalid/missing organization reference on assign/register => `InvalidOrganizationReferenceError`.
- Metadata/URL/organization changes preserve the facility’s UUID.
- Clearing canonical URL is allowed (sets canonical/normalized/domain to null), enabling later re-registration of that URL by another record only if not conflicting at time of use.

## Acceptance conditions (Milestone 1)

- `Apollo Hospitals` organization can own `Apollo Hospital Delhi` and `Apollo Hospital Chennai` as **different UUIDs**, independently retrievable/updatable, same `organization_id`.
- Facilities remain separate even if sharing the same website domain.
- Duplicate normalized facility URL rejected with conflict identifying existing facility.
- Same domain but different facility-specific URL succeeds.
- Facility without canonical URL succeeds.
